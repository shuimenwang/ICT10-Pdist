# 06 · 第一轮实现与优化总结

> 日期：2026-10-20 ~ 10-21 ｜ 硬件：Atlas 800T A2（910B3 x4，本报告用单卡） ｜ CANN 9.1.0
> 结论速览：正确性 56/56 全绿；(4096,512) p=2 达 **33.3 ms**，为 torch_npu 原生的 **4.0x**、PyTorch CPU 的 **1.9x**，较本仓 v0 基线提升 **2.17x**。

## 1. 第一轮实现（功能正确 → 场景稳定）

### 1.1 工程与调用链

msopgen 生成 aclnn 自定义算子工程（`--preset=default`，`ASCEND_COMPUTE_UNIT=ascend910b`），交付三份源文件：

| 文件 | 职责 |
|---|---|
| `op_host/pdist.cpp` | 算子原型注册（Input x / Output y，Attr p=2.0 可选）、InferShape、Tiling 计算、`SetBlockDim` |
| `op_kernel/pdist.cpp` | Ascend C Kernel：`KernelPdist<T, P_MODE>` 模板（T∈{half,float}，P_MODE∈{0,1,2,泛p}） |
| `op_kernel/pdist_tiling.h` | Host/Kernel 共享 POD Tiling 结构（纯 `<cstdint>`，避开 `kernel_type.h` 宏冲突） |

加载链路：`.run` 包安装到个人 OPP 目录 → `ASCEND_CUSTOM_OPP_PATH` → aclnn 两段式
（`aclnnPdistGetWorkspaceSize` → `aclnnPdist`）→ 驱动 `tests/driver/pdist_driver.cpp` 计时与落盘。

### 1.2 语义与关键设计

- 输出按上三角行主序展开：`y[i*(2N-i-1)/2 + (j-i-1)]`，与 `torch.nn.functional.pdist` 逐元素一致。
- p 分派在 Host 侧做（`ResolvePMode`：|p|<1e-6→0、|p-1|<1e-6→1、|p-2|<1e-6→2、否则泛 p），泛 p 的幂运算用 `ln→×p→exp` 实现；`1/p` 由 Host 预计算，Kernel 不做除法。
- 负载均衡按 **pair 均摊**而非按行均摊：行 i 的 pair 数 = N-1-i，按行切必倾斜；按 pair 切后各核 `pairPerCore(+1)` 严格均衡。
- pair 序号 → (i, j) 反解用**顺序推进减法**（标量域无 sqrt 接口，且单核起点只需一次 O(N) 推进）。
- 数值口径：FP16 输入 Cast 到 FP32，差值/幂/归约全程 FP32，最后 Cast 回原 dtype —— 精度与 torch FP32 oracle 对齐（FP16 输出按 ±1 ulp 口径比对）。

### 1.3 场景覆盖与正确性

- 四个 p 分支 × FP32/FP16 × 形状矩阵（最小 N=2 M=1、非对齐 M=131/959/1022/1023、大 M、大 N=4096）：**56/56 PASS**。
- FP16 判据：与 `y_ref.half().float()` 比对（atol=1e-3, rtol=2e-3，覆盖 fp16 相对 ulp ≤ 2^-10）；FP32 判据 atol=rtol=1e-4。
- 排错记录（复用价值高）：
  - `DataCopyPad` 的 **UB 侧 dstStride 不生效**（UB 目的必须连续），j 行批量搬运需紧凑布局 + `RowStride` 对齐回退；
  - `SetFlag/WaitFlag` 事件 ID 必须 `GetTPipePtr()->FetchEventID(...)` 动态获取，硬编码会与 TQue 内部事件撞车；
  - TilingKey 只能取 0（工程只编译 key=0 变体），p/dtype 分派放 Kernel 内运行时分支；
  - `log/log.h`、`aclnnSynchronizeStream` 等接口不存在，分别用现有接口 / `aclrtSynchronizeStream` 替代。

## 2. 第一轮优化（通用昇腾算子策略）

### 2.1 四项策略

| # | 策略 | 做法 | 收益来源 |
|---|---|---|---|
| 1 | 行 i 常驻 UB | 一行 i 只搬一次服务整行 j（M≤K_BLOCK=1024 时整行常驻） | HBM 读流量 2x → 1x |
| 2 | j 行批量 TJ=8 | 连续 8 行 j 一条 2D DMA 搬入、8 个输出一次写回 | DMA 指令数 ÷8，MTE2/V 流水重叠 |
| 3 | Double Buffering | `TQue` 深度 2，下一 tile 搬运与当前 tile 计算重叠 | MTE2 与 V 并行 |
| 4 | 标量/除法下放 | p、1/p、Tiling 全部落 Host；p=2 走 Sub+Mul 不碰 ln/exp | 减少标量域与超越函数开销 |

### 2.2 途中修复的两个正确性问题

1. **j 行布局**：`DataCopyPad` UB 侧 dstStride 不生效 → 引入 `RowStride(len)=align8(len)`，对齐长度走单条 2D DMA（GM 侧 srcGap 跳行），非对齐长度逐行搬入 `dst[b*stride]`；并将 blockLen 向上对齐 32B，规避非对齐 blockLen 的尾部异常。
2. **p=0 非对齐尾部**：`Compares`+`VSEL_TENSOR_SCALAR_MODE` 在非 64 对齐长度下尾部掩码语义不可靠（M∈{1022,1023} 丢尾部 [960,len)）。最终改为**整数域位技巧**，完全绕开比较/掩码指令：
   `t = bitcast(|d|)`（|d| 符号位 0 → t 非负，d==0 ⟺ t==0）→ `(t-1)>>31`（0→-1，非零→0）→ `+1`（得 0/1）→ `Cast` 回 float。仅 4 条确定性 V 指令（Sub/ShiftRight/Add/Cast）。

### 2.4 归因链

- v0 瓶颈：每 pair 现搬两行（HBM 读 2x）+ 每 pair 3 次 DMA + 逐元素写回 → (4096,512) p=2 72.3ms。
- v1 消除：读流量减半（~17GB → 8.6GB 量级）、DMA 指令数 ÷8、MTE2/V 双缓冲重叠 → **33.3ms（2.17x）**。
- 剩余差距：v1 ≈ 33ms，而 (4096,512) 的 x 矩阵仅 8MB；按 pair 均摊后每行 i 仍被重复读 ~N/2 次，HBM 有效读流量 ~17GB（x 全矩阵 × ~2047 次行复用 ÷ 8 行批量 = 每行读 ~N/8 次）。理论读带宽界 ~14ms（1.2TB/s 计），当前距硬件上限 **~2.4x** —— 引出第二轮「i-block 二维分块」再降读流量 + p=2 走 Cube 路线的空间。
