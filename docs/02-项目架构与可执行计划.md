## 1. 目标分解（对齐初赛真实交付物）

初赛是**方案提交制 + 性能排名**，因此每层目标都必须同时产出"算子能力"与"可写进答卷的证据"。

| 目标层 | 内容 | 验收标准（DoD） | 服务于 |
|---|---|---|---|
| G1 功能正确 | 对标 PyTorch pdist 全分支（p=0/1/2/泛 p）× FP16/FP32 | 全用例与 CPU oracle 误差 ≤1e-4（FP32）/ ≤2e-3 相对误差（FP16 出入） | 答卷"精度优化"章节 |
| G2 场景稳定 | 四大切分场景全触发 + 边界（N=1、M=1、非对齐、超大 M=133177） | 回归矩阵全绿，连续 3 次无波动，无核挂死/内存告警 | 答卷"工程完备性" |
| G3 性能拉满 | 全面超越原生基线（FP32 (4096,512) p=2 ≈133ms、p=0 ≈2087ms 为参照），精度反超原生 FP16 | 主场景 ≥3× 原生加速；p=0 ≥5×；FP16 精度优于原生实测值；每项优化有前后数据与归因 | 答卷"性能排名"主张 |
| G4 可答辩 | 每个优化有归因链 | 现场 5 分钟讲清任意设计决策；答卷按 docs/05 骨架成文 | 方案评审得分 |

## 3. 核心设计决策（先定原则，再写代码）

### 3.1 Tiling 决策树（Host 侧）

```text
输入 X: (N, M)，UB 可用字节 U
│
├─ 整行 (M×dtype) 放得下 UB？──是──→ 场景①：整行单轮，行对循环
│        否
├─ 输出对数能否多核摊平？──是──→ 场景③：按输出行块切核，尾块均摊
│        否/叠加
├─ 按特征维 M 切块：block = floor(U / 行宽)，多轮核内累加（场景②）
│
└─ 块尾非 32B 对齐？──是──→ 场景④：Pad 到对齐 + Mask 过滤
```

配套原则：优先按行切（Pdist 按行对组织的天然粒度）；尾行均摊严禁单核扛尾巴；块大小 32B 向上取整 + Pad/Mask。

### 3.2 TilingKey 编码规范（单源）

- 位定义：`[3] dtype(0=FP16,1=FP32) | [2:1] 场景(①②③④) | [0] 对齐(0=对齐,1=非对齐)`
- 定义只存在于 `op_host/pdist_tiling.h`，Kernel `#include` 同一文件，杜绝 31361001 找不到 Kernel。

### 3.3 精度策略

- 输入 FP16 → cast FP32；中间（差值/幂/ln/exp/累加）全程 FP32；输出前 cast 回原类型。
- `1/p`、标量常量 Host 预计算，随 Tiling 结构体下发。
- p=0 特殊分支：差值非零置 1、零置 0，归约求和即非零维计数。
- 验收线：FP32 逐元素绝对误差 ≤1e-4；FP16 输入相对误差 ≤2e-3（对齐 torch_npu FP32 实测 7.6e-6 的量级差距意识）。

### 3.4 多核与内存纪律

- 核内结果按输出对索引定位写回，禁止多核写同一地址。
- AllocTensor/FreeTensor 严格配对；UB 偏移逐项验算 32B 对齐。
- 编译/缓存只进 `/cache`（work 盘仅 4.6G 余量）。

## 5. 测试体系（oracle 独立）

| 用例类型 | 覆盖 | 断言 |
|---|---|---|
| 精度 | p∈{0,0.5,1,1.5,2,3} × FP16/FP32 × (N,M)∈{(1,M),(2,1),(64,128),(512,256),(1024,512)} | 逐元素 ≤1e-4（FP32）|
| 边界 | M=133177、非对齐 M=131、N=1、整除/不整除、tail | 无越界、无挂死、结果正确 |
| 切分 | 场景①②③④ 各自触发 | Tiling 打印值与手算一致 |
| 性能 | 基线场景 × ≥3 次取均值 | 达标 + PMU 归档 |

原则：**oracle 只认 PyTorch 原生输出（CPU 侧）**；每个用例可独立复跑；隐藏用例不做猜测，只覆盖公开语义。
