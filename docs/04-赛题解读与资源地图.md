**对本项目的关键推论**：

1. 初赛交付物 = **方案答卷（文档）**，但方案必须有可信的性能/精度数据支撑 → 本项目"算子工程 + 实测数据"就是答卷的证据链。
2. "根据性能进行排名" → 必须有**明确的性能基线与归因链**（为什么快、快多少、证据在哪）。

## 2. Pdist 赛题技术要求拆解

**功能语义**（与 `torch.nn.functional.pdist` 严格对齐）：

- 输入 `x`：形状 `(N, M)`，FP32/FP16，ND；输出 `y`：形状 `(N*(N-1)/2,)`，行两两距离，按 `(i<j)` 行主序展开。
- 距离公式 `d(x_i, x_j) = (Σ_k |x_ik - x_jk|^p)^(1/p)`。
- p 分支：p=0（非零差计数）、p=1（曼哈顿）、p=2（欧氏，默认）、泛 p（ln+exp 通路）。p=inf 按 PyTorch 文档不在 pdist 范围内（0 ≤ p < inf；赛题覆盖范围以任务书为准，推断不含 inf）。
- 参考实现只认 PyTorch 原生输出（CPU 侧 oracle）。

**本机实测事实（2026-10-20，910B3 + torch_npu 2.7.1.post2）**：

| 实验 | 结果 | 含义 |
|---|---|---|
| `torch.pdist` FP32 @ NPU (512,256) | 可运行，与 CPU oracle 误差 7.6e-6 | FP32 正确性基线可建立 |
| `torch.pdist` FP16 @ NPU (256,128) | **可运行但精度差**：p=2 差 0.016，p=1 差 0.125（vs CPU FP32 oracle）；速度也不占优（127.6ms vs FP32 133.2ms @ (4096,512)） | 原生 FP16 疑似 FP16 全程计算；自研"FP32 中间计算"版可同时反超精度与速度 |
| (4096,512) FP32 各 p 值耗时 | 均约 133-134 ms/次 | 原生走通用路径、未按 p 分支优化，**优化空间巨大** |
| (4096,512) FP32 p=0 | **2087 ms，慢 15.6 倍** | p=0 专用路径严重低效，首个可拿分优化点 |
| 大 M 累加误差 | M=256 → 1.5e-4；M=133177 → 6.1e-4（均 NPU 原生 vs CPU） | 精度判据必须用"绝对+相对"双容差，且任务书口径优先 |
| p=inf @ NPU FP32 (64,64) | 可运行 | p 分支行为需在任务书范围内核对 |

**性能基线表（初版，作为排名参照系）**：见 [results/baseline_native_20261020.md](../results/baseline_native_20261020.md)，由 `tests/test_pdist_perf.py` 一键复现。
